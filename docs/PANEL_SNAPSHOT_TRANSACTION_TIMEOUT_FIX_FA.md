# رفع خطای PendingRollbackError در بررسی سرویس‌های منقضی

## علت

در نسخه قبلی، تابع verified_panel_snapshot کل بررسی پنل و اعمال نتیجه در دیتابیس را با مهلت ۱۲ ثانیه اجرا می‌کرد. طبق لاگ ارسالی، این مهلت هنگام autoflush مربوط به آزادسازی رزرو حجم نماینده تمام شده است. لغو عملیات دیتابیس، تراکنش را نیازمند rollback کرده و دسترسی بعدی به شناسه ORM منقضی‌شده باعث PendingRollbackError شده است.

این لاگ چند مرحله از یک زنجیره خطا را نشان می‌دهد؛ به‌تنهایی خرابی دیتابیس یا مشکل CPU/VPS را ثابت نمی‌کند. علت تأخیر عملیات دیتابیس نیز از همین لاگ به‌تنهایی مشخص نیست.

## اصلاح

- مهلت ۱۲ ثانیه صرفاً روی دریافت اطلاعات پنل اعمال می‌شود.
- اعمال مصرف، وضعیت و انقضا، آزادسازی رزرو حجم و تطبیق حسابداری نماینده در تراکنش فراخواننده اجرا می‌شوند و با مهلت ارتباط پنل لغو نمی‌شوند.
- خطای دیتابیس به عنوان قطع ارتباط پنل پنهان نمی‌شود و به فراخواننده می‌رسد تا rollback انجام دهد. اسکن پاکسازی از قبل rollback و ثبت خطای اصلی را انجام می‌دهد.
- شناسه‌های مورد نیاز پیش از await گرفته می‌شوند و در مسیر خطا برای نوشتن کش یا لاگ دوباره از ORM خوانده نمی‌شوند.
- قطع ارتباط یا timeout پنل همچنان نتیجه تأییدنشده می‌دهد؛ اطلاعات تأییدنشده باعث ورود جدید سرویس به صف حذف نمی‌شود.

## بررسی

آزمون‌های اختصاصی شامل کندبودن به‌روزرسانی دیتابیس بیشتر از مهلت شبکه، کندبودن تطبیق رزرو حجم نماینده، timeout واقعی ارتباط شبیه‌سازی‌شده و خطای واقعی محدودیت دیتابیس و بازیابی با rollback هستند. آزمون‌های انقضا، هشدار حجم، سیاست پاکسازی و مسیرهای مرتبط قبلی نیز اجرا شده‌اند. بررسی‌ها محلی با SQLite و پاسخ شبیه‌سازی‌شده پنل انجام شده‌اند؛ PostgreSQL/VPS و پنل واقعی در دسترس نبودند.

## اعمال

این بسته کامل و تجمعی است؛ خروجی‌های وب‌پنل و اصلاحات قبلی حفظ شده‌اند. فایل‌ها را جایگزین کنید، .env و دیتابیس را نگه دارید و اجرا کنید:

```bash
docker compose up -d --build api bot
```

تغییر ساختار دیتابیس یا دستکاری دستی داده‌ها برای این اصلاح لازم نیست.
