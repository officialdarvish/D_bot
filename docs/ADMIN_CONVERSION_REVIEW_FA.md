# مدیریت درخواست‌های تغییر تعرفه خطادار — 1.3.0

مدیریت ربات → بررسی مجدد درخواست‌های تغییر تعرفه.

- درخواست‌های خطادار با شناسه کاربر، کانفیگ مبدأ، مقصد و خطای ثبت‌شده نمایش داده می‌شوند.
- بررسی مجدد پنل‌ها فقط وضعیت را می‌خواند.
- «حذف و آزادسازی درخواست» پس از تأیید مدیر، نبود قطعی مقصد را بررسی می‌کند. در صورت وجود مقصد یا نامشخص‌بودن وضعیت، درخواست آزاد نمی‌شود و دلیل مشخص نمایش داده می‌شود.
- اگر مقصد ساخته نشده و مبدأ غیرفعال شده باشد، فقط وضعیت مبدأ دوباره فعال و تأیید می‌شود؛ حجم، مصرف، تاریخ انقضا و گروه‌ها تغییر نمی‌کنند.
- پس از آزادسازی، کاربر می‌تواند از کانفیگ‌های من پیش‌نمایش تازه بگیرد. رکورد رزرو قبلی به‌صورت اتمیک برای تلاش جدید استفاده می‌شود؛ تبدیل‌های موفق یا در حال اجرا قابل آزادسازی نیستند.
- درخواست‌های آزادشده در «درخواست‌های حذف‌شده» تا شروع تلاش بعدی قابل مشاهده‌اند. بازگرداندن به بررسی، دوباره آن‌ها را قفل می‌کند.
- درخواست‌هایی که در نسخه قبل فقط آرشیو شده‌اند هنگام تلاش صریح بعدی کاربر بررسی و، در صورت تأیید پنل‌ها، آزاد می‌شوند.
- پیش‌نمایش‌ها و تأییدهای صف‌شده قدیمی مینی‌اپ با آزادسازی باطل می‌شوند. نتیجه خطادار ذخیره‌شده در مرورگر مسیر تازه را مسدود نمی‌کند.

## مسیر تبدیل

در ربات و مینی‌اپ: کانفیگ‌های من → انتخاب کانفیگ → تبدیل تعرفه → انتخاب دسته قابل تبدیل → محاسبه و پیش‌نمایش → تأیید نهایی.

هیچ انتخاب پلن یا سرور دیگری از کاربر خواسته نمی‌شود. قالب ساخت به‌صورت داخلی از اولین سرور مجاز در ترتیب تنظیمات Convert و سپس کمترین شناسه پلن معتبر و محدود آن دسته انتخاب می‌شود. مبلغ پلن و حجم بسته، مبنای محاسبه تبدیل نیست؛ نرخ گیگ دسته‌های مبدأ و مقصد و حجم باقی‌مانده واقعی پنل مبنا هستند. انقضای قبلی حفظ می‌شود.

دسته باید یک پلن محدود فعال روی سرور پشتیبانی‌شده و مجاز داشته باشد. API قبلی target_plan_id برای سازگاری باقی است؛ رابط جدید target_category_id ارسال می‌کند.

## نصب

نسخه کامل را جایگزین کنید و .env و دیتابیس را نگه دارید:

```sh
docker compose up -d --build api bot
```

نیازی به تغییر ساختار دیتابیس یا متغیر جدید نیست. تست‌ها محلی و با پنل‌های شبیه‌سازی‌شده انجام شده‌اند؛ روی VPS واقعی تغییری انجام نشده است.
