# رفع Deadlock هنگام همگام‌سازی و پاکسازی سرویس‌ها

لاگ جدید خطای واقعی PostgreSQL با کد 40P01 را نشان می‌دهد: دو تراکنش منتظر قفل یکدیگر مانده‌اند. خطا هنگام بروزرسانی reserved_bytes حساب نمایندگی رخ داده است. کوئری کامل تراکنش مقابل در فایل ارسالی نیست؛ بنابراین تمام جزئیات آن چرخه از لاگ به‌تنهایی مشخص نیست.

در کد، مسیرهایی با ترتیب «سرویس سپس حساب نماینده» و مسیرهایی با ترتیب معکوس وجود داشت. همچنین کارهای دوره‌ای، قفل چند سرویس و چند حساب را تا پایان یک فهرست بزرگ نگه می‌داشتند. این دو مورد زمینه ایجاد چرخه قفل را فراهم می‌کردند.

## تغییرات

- در مسیر مشترک حسابداری و دریافت وضعیت پنل، حساب نماینده پیش از قفل یا autoflush سرویس گرفته می‌شود. هنگام گرفتن قفل حساب، no_autoflush فقط مانع ثبت زودهنگام سرویس می‌شود؛ محاسبه و ثبت حسابداری حذف نشده است.
- مسیر افزودن زمان در ربات و بروزرسانی مصرف در مینی‌اپ نیز حساب نماینده را قبل از سرویس قفل می‌کنند. در مینی‌اپ حساب‌های چندگانه به ترتیب شناسه قفل می‌شوند.
- پاکسازی دوره‌ای برای هر سرویس Session و تراکنش جدا دارد؛ خرابی یک سرویس باقی فهرست را rollback نمی‌کند.
- همگام‌سازی مصرف پاسارگارد و MikroTik نیز برای هر سرویس تراکنش جدا دارد.
- بررسی اعلان‌ها تراکنش جدا برای هر سرویس دارد. کش خواندن پنل سنایی در همان اسکن مشترک باقی می‌ماند تا تعداد درخواست شبکه زیاد نشود.
- تراکنش‌های دریافت وضعیت و صف‌گذاری پاکسازی، فقط برای Deadlock تأییدشده با SQLSTATE=40P01 تا مجموع سه تلاش اجرا می‌شوند. هر تلاش بعد از rollback و بستن Session قبلی، با Session تازه و فاصله کوتاه انجام می‌شود. سایر خطاها خودکار تکرار نمی‌شوند.
- حذف واقعی از پنل و ارسال اعلان‌های حذف، خارج از این حلقه تلاش مجدد و بعد از ثبت موفق صف انجام می‌شوند. مسیر ارسال پیام هشدار نیز داخل حلقه تلاش مجدد دیتابیس قرار نگرفته است.
- مهلت ۱۲ ثانیه همچنان فقط به خواندن پنل مربوط است و عملیات دیتابیس را قطع نمی‌کند.
- بررسی تازه پنل و مهلت ۷۲ ساعته سرویس عادی / ۶ ساعته تست حفظ شده‌اند. در زمان در دسترس نبودن پنل، سرویس تازه وارد صف حذف نمی‌شود.

## بررسی و محدودیت

۱۲۲ آزمون محلی موفق بود. آزمون‌های جدید، ترتیب دستورهای قفل با کامپایل PostgreSQL، خطای 40P01 شبیه‌سازی‌شده، rollback کامل، Session تازه برای هر تلاش، سقف تلاش‌ها، عدم تکرار تغییرات دیتابیس و جدابودن عملیات خارجی از تلاش مجدد را بررسی می‌کنند. سیاست پاکسازی، تمدید دستی پنل، هشدار حجم، حسابداری نمایندگی، PAYG، مینی‌اپ و اصلاح timeout قبلی نیز بررسی شدند.

این تست‌ها با SQLite و پاسخ‌های شبیه‌سازی‌شده پنل اجرا شدند؛ آزمایش همزمانی روی PostgreSQL و VPS واقعی انجام نشده است. این اصلاح، ترتیب قفل و دامنه تراکنش را اصلاح می‌کند و بازیابی محدود از Deadlock دارد؛ تضمین حذف هر نوع Deadlock از تمام مسیرهای پروژه نیست.

## نصب

این بسته کامل و تجمعی است و فایل‌های خروجی وب‌پنل و اصلاحات قبلی را حفظ می‌کند. فایل‌های پروژه را جایگزین کنید و .env و دیتابیس را نگه دارید. سپس اجرا کنید:

```bash
docker compose up -d --build api bot
```

برای این اصلاح، تغییر ساختار دیتابیس یا حذف دستی اطلاعات لازم نیست.
