# حذف کانفیگ فقط از لیست ربات — D Bot 1.3.0

مسیر: مدیریت ربات → تعامل با کاربر → «حذف کانفیگ از لیست ربات».

۱. آخرین لینک کامل ساب ثبت‌شده را در گفت‌وگوی خصوصی ربات بفرستید.
۲. نام کانفیگ، سرور، نام مالک، یوزرنیم و آیدی عددی مالک نمایش داده می‌شود.
۳. با تأیید نهایی، کانفیگ از فهرست صاحب آن در ربات و مینی‌اپ پنهان می‌شود.

این عملیات هیچ API پنلی را فراخوانی نمی‌کند. کانفیگ داخل پنل باقی می‌ماند؛ وضعیت فعال‌بودن، مالکیت، حجم، مصرف، انقضا، گروه‌ها، کیف پول و سوابق خرید تغییر نمی‌کنند. رکورد سرویس نیز از دیتابیس پاک نمی‌شود. فقط یک نشانگر نمایش و سابقه اقدام مدیر ثبت می‌شود.

سرویس پنهان‌شده در صف حذف خودکار ربات قرار نمی‌گیرد و هشدار تمدید برای آن ارسال نمی‌شود. حسابداری نمایندگی همچنان حفظ می‌شود. انقضا یا محدودیت‌های خود پنل مانند قبل برقرارند.

نکات:

- دسترسی فقط برای مدیر ربات است؛ تأیید ۱۰ دقیقه اعتبار دارد و تکرار دکمه قدیمی عملیات تازه‌ای انجام نمی‌دهد.
- تغییر مالک یا لینک بین پیش‌نمایش و تأیید، تأیید قبلی را باطل می‌کند.
- لینک‌های HTTP/HTTPS، لینک Happ crypt5 ثبت‌شده و پوشش happ://add/ پشتیبانی می‌شوند. لینک ورودی از اینترنت خوانده نمی‌شود؛ تطبیق با اطلاعات ذخیره‌شده است.
- لینک تکراری میان چند سرویس، لینک پیدا‌نشده یا سرویس دارای حذف، تبدیل یا پرداخت در انتظار، پیام مشخص دریافت می‌کند و تغییری انجام نمی‌شود.
- سرویس همچنان در اطلاعات مدیریتی و سوابق مالی باقی می‌ماند. این گزینه با حذف واقعی کانفیگ از پنل متفاوت است.

## نصب روی نسخه قبلی

فایل‌های پروژه را جایگزین کنید و .env و دیتابیس را نگه دارید، سپس:

```sh
docker compose up -d --build api bot
```

ستون hidden_from_owner به‌صورت خودکار و بدون حذف اطلاعات توسط API و ربات اضافه می‌شود. ساختار جدید روی SQLite قدیمی و حالت اجرای دوباره مهاجرت تست شد. خروجی‌های آماده وب و مینی‌اپ نیاز به تغییر ندارند و در بسته حفظ شده‌اند.

۱۱۹ تست مرتبط شامل جست‌وجوی لینک، تأیید و انصراف، دسترسی مدیر، تغییر مالک یا لینک، حفظ اطلاعات، جلوگیری از حذف خودکار، کنترل مالکیت و تبدیل تعرفه موفق شد. تست‌ها محلی بوده‌اند و روی پنل یا VPS واقعی عملیاتی انجام نشده است.
