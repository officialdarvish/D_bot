# رفع نبودن ماژول انتقال مالکیت در کانتینر

لاگ `ModuleNotFoundError: No module named 'app.services.service_ownership'` نشان می‌دهد هندلر دکمه در نسخه اجراشده وجود دارد، اما ماژول لازم در دسترس مفسر همان کانتینر نیست. فایل `app/services/service_ownership.py` در نسخه‌های کامل قبلی وجود دارد. نصب ناقص، ساخت از مسیر سورس دیگر، ایمیج قدیمی یا جایگزینی سورس با mount از علت‌های ممکن هستند؛ بدون دسترسی به VPS نمی‌توان یکی را قطعی دانست.

## اعمال نسخه کامل

تمام محتوای ZIP جدید را در پوشه پروژه اجراشده جایگزین کنید. در نصب پیش‌فرض، مسیر `/opt/d-bot` است. فایل `.env` و داده‌های پایگاه‌داده نصب فعلی را نگه دارید.

از داخل همان پوشه اجرا کنید:

```bash
python3 scripts/check_runtime_files.py &&
docker compose up -d --build --force-recreate api bot
```

بررسی جدید بدون نیاز به توکن یا اتصال دیتابیس، وجود فایل‌های ضروری و توابع آن‌ها را کنترل می‌کند. Docker نیز همین بررسی را بعد از کپی سورس اجرا می‌کند و ساخت ایمیج ناقص را متوقف می‌کند.

سپس وجود ماژول در کانتینر اجراشده را بررسی کنید:

```bash
docker compose exec bot python -c "import app.services.service_ownership; print('Ownership module OK')"
```

اگر پیام بالا دریافت شد، از منوی تازه «کانفیگ‌های من» دکمه انتقال مالکیت را امتحان کنید.

## اگر هنوز فایل در کانتینر پیدا نشد

در همان پوشه پروژه، وجود فایل روی میزبان را بررسی کنید:

```bash
ls -l app/services/service_ownership.py
```

پیکربندی‌های سفارشی `docker-compose.override.yml`، `build.context` و mount روی `/app` یا `/app/app` می‌توانند سورس دیگری را جایگزین کنند. آن مسیر هم باید شامل فایل‌های کامل همین نسخه باشد.

هیچ تغییری در منطق انتقال، دیتابیس یا مالکیت سرویس‌های فعلی برای رفع این خطای نصب لازم نیست. تا قبل از دریافت آیدی مقصد، خود دکمه مالکیت سرویس را تغییر نمی‌دهد.
