# اصلاح قطع ارتباط تلگرام هنگام پاسخ اولیه دکمه

خطای ارسالی در پاسخ اولیه answerCallbackQuery اتفاق می‌افتاد؛ قبل از رسیدن پردازش به فرمان اصلی دکمه، خطای شبکه به بیرون منتقل می‌شد.

- پاسخ اولیه و پیام‌های پاسخ دکمه در نقطه مشترک ارسال مدیریت می‌شوند، از جمله پاسخ دکمه مشغول و پیام منقضی.
- پاسخ دکمه حداکثر ۳ ثانیه منتظر شبکه می‌ماند. قطع ارتباط، timeout، خطای موقت سرور تلگرام و محدودیت نرخ این پاسخ، فرمان اصلی را متوقف نمی‌کند.
- این خطا به‌صورت هشدار کوتاه در لاگ ثبت می‌شود. handler تجاری تکرار نمی‌شود و خرید، ساخت یا حذف به‌خاطر شکست پاسخ اولیه مجدداً اجرا نمی‌شود.
- دکمه منقضی فعال نمی‌شود و قفل پردازش درخواست قبلی حفظ می‌شود.
- لغو پردازش و خطاهای غیرمنتظره مخفی نمی‌شوند. این رفتار فقط پاسخ دکمه را پوشش می‌دهد؛ خطای ارسال پیام یا عملیات اصلی همچنان خطا محسوب می‌شود.

این اصلاح اختلال دائمی اتصال VPS به api.telegram.org را برطرف نمی‌کند. اگر ارتباط برقرار نباشد، ارسال نتیجه یا ویرایش پیام همچنان ممکن است شکست بخورد.

اعتبارسنجی با aiogram dispatcher و انتقال تلگرام شبیه‌سازی‌شده انجام شد: قطع اتصال، timeout، درخواست معلق، خطای سرور، محدودیت نرخ، پاسخ بدون context، حالت داخلی، دکمه منقضی و دکمه مشغول. تست روی VPS و تلگرام واقعی انجام نشده است. خروجی وب و اصلاحات قبلی حفظ شده‌اند.

بعد از جایگزینی سورس و با حفظ فایل محیط و دیتابیس:

```sh
docker compose build api bot && docker compose up -d --no-build api bot
```
