# افزودن دستی نماینده و نمایش خطاهای API

این بسته کامل و تجمعی D Bot 1.3.0 است و اصلاحات قبلی وب‌پنل، مسیردهی، timeout و Deadlock را حفظ می‌کند.

## علت و اصلاح

پیام `[object Object]` متن واقعی خطا نبود. API ممکن است خطای اعتبارسنجی را به شکل آرایه‌ای از فیلدهای نامعتبر یا یک شیء تو‌در‌تو برگرداند. سه تابع مشترک درخواست وب، این پاسخ را مستقیماً به Error می‌دادند و JavaScript شیء را به `[object Object]` تبدیل می‌کرد.

یک مبدل مشترک و محدود برای خطاها اضافه شده است. خطای متنی، Error، آرایه اعتبارسنجی FastAPI و ساختارهای message/detail/errors/error به متن خوانا تبدیل می‌شوند. نام فیلدهایی مانند آیدی تلگرام، حجم، روزها و سرورها در خطا مشخص می‌شود. نوع‌های رایج اعتبارسنجی متن فارسی و انگلیسی دارند. داده خام input، اطلاعات ctx، stack و اشیای ناشناخته نمایش داده نمی‌شوند؛ برای پاسخ ناشناخته، پیام جایگزین مشخص می‌آید.

این مبدل در درخواست‌های مشترک وب‌پنل، اعلان عمومی، خطای تنظیمات، بازیابی بکاپ، ورود مدیر از مینی‌اپ، درخواست‌های مینی‌اپ، QR و آپلود رسید مسیرهای خرید و نمایندگی اعمال شده است. کنترل انقضای نشست و AUTH_REQUIRED حفظ شده است.

در افزودن نماینده، حجم اولیه فقط عدد صحیح پذیرفته می‌شد، در حالی که ویرایش نماینده حجم اعشاری داشت. افزودن نیز حجم اعشاری مانند 0.1 و 12.5 را می‌پذیرد و با Decimal به بایت صحیح تبدیل می‌کند. آیدی نامعتبر، حجم منفی یا خارج از محدوده، و تعداد روز منفی یا غیرقابل نمایش پیش از ایجاد رکورد رد می‌شوند. فرم نیز برای حجم، گام اعشاری و برای آیدی و روزها گام صحیح و حداقل مناسب دارد.

خطاهای معتبر ورودی همچنان مانع ثبت می‌شوند؛ تفاوت این است که علت و فیلد مشکل‌دار خوانا نمایش داده می‌شود. صرف دیدن `[object Object]` مشخص نمی‌کند کدام فیلد در درخواست واقعی نامعتبر بوده است؛ بدون متن درخواست یا پاسخ واقعی، نمی‌توان علت دقیق همان ارسال کاربر را قطعی دانست.

## بررسی

- ۵۵ آزمون Python موفق: ایجاد نماینده با حجم صحیح/اعشاری، ویرایش اعشاری، درخواست تکراری، رد ورودی نامعتبر بدون ایجاد کاربر/حساب، گروه‌های اینباند، مدیریت مالی و وب.
- ۵ آزمون Node موفق: آرایه خطای FastAPI، پیام تو‌در‌تو، ورودی ناشناخته و چرخه‌ای، هر سه تابع مشترک API، حفظ AUTH_REQUIRED، پاسخ HTML و JSON خراب.
- TypeScript و ساخت production موفق؛ خروجی‌های frontend/out و frontend_out بازسازی و یکسان شدند.

تست‌ها محلی‌اند؛ ثبت روی VPS و پنل واقعی انجام نشده است.

## اعمال

فایل‌ها را جایگزین کنید و فایل .env و دیتابیس فعلی را حفظ کنید. سپس:

```bash
docker compose up -d --build api bot
```

تغییر ساختار دیتابیس لازم نیست.
