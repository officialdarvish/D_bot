# بررسی خرید با کیف پول مینی‌اپ روی PasarGuard

این بسته بر مبنای آخرین اصلاح حجم تست نسخه 1.3.0 است و آن اصلاحات را حفظ می‌کند.

## ایرادهای بازتولید و اصلاح‌شده

- اگر قالب پاسارگارد به نام کاربر پیشوند/پسوند اضافه می‌کرد، نام درخواستی اولیه در سرویس ربات ذخیره می‌شد. اکنون نام واقعی پاسخ پنل هم برای خواندن/نوشتن‌های بعدی و هم ذخیره سرویس استفاده می‌شود. جزئیات سفارش تکمیل‌شده نیز همان نام واقعی را نشان می‌دهد؛ نام اولیه در متادیتای درخواست باقی می‌ماند تا تکرار همان کلید خرید معتبر باشد.
- اگر ایجاد کاربر موفق می‌شد اما لینک اشتراک در پاسخ ایجاد یا خواندن نهایی موجود نبود، سفارش paid می‌شد. اکنون این حالت برای بررسی مدیر متوقف می‌شود و سفارش بدون لینک تکمیل‌شده محسوب نمی‌شود. ایجاد مجدد خودکار انجام نمی‌شود، چون کاربر ممکن است روی پنل ساخته شده باشد.

## رفتار مالی و بازیابی

کسر موجودی، تراکنش کیف پول و ایجاد سفارش در یک تراکنش دیتابیس انجام می‌شوند. ارسال دوباره همان کلید خرید، سفارش قبلی را برمی‌گرداند. در خطای نامشخص پنل یا نبود لینک، وجه به شکل خودکار برنمی‌گردد و سفارش برای بررسی مدیر باقی می‌ماند؛ احتمال ساخت واقعی اکانت مانع از بازپرداخت یا ساخت مجدد خودکار است. این سیاست مالی قبلی تغییر نکرده است. خطای تلگرام پس از ثبت paid نیز خرید را دوباره کسر یا سرویس را دوباره ایجاد نمی‌کند و کانفیگ در مینی‌اپ قابل دریافت است.

## اعتبارسنجی

119 تست مرتبط با کیف پول و خرید مینی‌اپ، ساخت پاسارگارد، نام تکراری، لینک پنل و سهمیه تست پاس شدند. شش حالت جدید از API واقعی خرید، صف پردازش، build_service و آداپتر پاسارگارد عبور می‌کنند؛ تنها ارتباط بیرونی پاسارگارد/تلگرام و بررسی موجود بودن نام شبیه‌سازی شده است: ساخت مستقیم، قالب با نام متفاوت، برخورد نام، لینک خالی، خطای نامشخص ارتباط و خطای ارسال تلگرام. یک‌بار کسر موجودی و تراکنش، عدم ایجاد مجدد با کلید تکراری، مالکیت سفارش، لینک دقیق پنل و دریافت لینک از مینی‌اپ بررسی شده‌اند.

تست‌ها با SQLite محلی و APIهای شبیه‌سازی‌شده اجرا شده‌اند. تست زنده روی پنل کاربر، پرداخت واقعی و رقابت تراکنش‌های PostgreSQL انجام نشده است.

## اجرا

فایل .env و دیتابیس خود را حفظ کنید، سورس پروژه را به‌روزرسانی کنید و سرویس‌های api و bot را با روش نصب فعلی بازسازی/راه‌اندازی کنید. در نصب Docker Compose از ریشه پروژه:

```bash
docker compose up -d --build api bot
```

این تغییر migration جدید ندارد و نام سرویس‌های قبلی را خودکار اصلاح نمی‌کند.
