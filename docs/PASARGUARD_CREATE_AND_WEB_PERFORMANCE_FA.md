# پایداری ساخت پاسارگارد و سرعت وب‌پنل

## ساخت کاربر

`ReadTimeout` یعنی پاسخ به‌موقع نرسیده است؛ از این خطا به‌تنهایی نمی‌توان فهمید کاربر در پنل ساخته شده یا نه. نسخه جدید روی هر POST ساخت یک شناسه تصادفی در فیلد `note` پاسارگارد می‌گذارد. اگر پاسخ ساخت قطع شود، بدون تکرار POST، نتیجه را با خواندن همان نام و بررسی شناسه درخواست بازیابی می‌کند. برای ساخت مستقیم، حجم، گروه‌ها و محدودیت دستگاه نیز باید با درخواست تطابق داشته باشند. حسابی با نام یکسان و شناسه متفاوت پذیرفته نمی‌شود.

برای Template، پیشوند/پسوند واقعی از Metadata یا خواندن Template گرفته می‌شود؛ جست‌وجوی فراگیر کاربران انجام نمی‌شود. محدودیت‌های تست، HWID و گروه‌های نماینده بعد از بازیابی نیز از مسیر موجود بررسی می‌شوند. اگر نتیجه قابل تأیید نباشد، پیام مشخصِ «نتیجه ساخت تأیید نشده» نمایش داده می‌شود؛ پیش از تکرار ساخت، مدیر باید پنل را بررسی کند. هیچ POST مبهمی خودکار دوباره ارسال یا با نام تازه تکرار نمی‌شود.

خواندن‌های بدون تغییر، در خطای موقت شبکه یک بار تکرار می‌شوند. توکن/پایه API در محدوده همان نمونه سرویس و وابسته به اثرانگشت مشخصات ورود، حداکثر ۱۲۰ ثانیه نگهداری می‌شود؛ تغییر رمز یا 401 باعث احراز هویت مجدد می‌شود. دسترسی‌ها و نتیجه کاربران کش نمی‌شوند.

بودجه پیش‌فرض اتصال ۸ ثانیه، خواندن عادی ۲۰ و پاسخ ساخت ۴۵ ثانیه است. بازخوانیِ نتیجه نامشخص حداکثر ۱۲ ثانیه فرصت دارد؛ بازخوانی اختیاری لینک هم محدود است. انتظار بیرونی ساخت نماینده پیش از تکمیل این بررسی قطع نمی‌شود. تنظیمات اختیاری جدید در `.env.example` با پیشوند `PASARGUARD_` آمده‌اند.

## وب‌پنل

- فونت Vazirmatn از فایل‌های محلی موجود بارگذاری می‌شود؛ وابستگی مسدودکننده به CDN خارجی حذف شده است.
- فایل‌های استاتیک، فونت‌ها، Health و مسیرهای ثابت API برای تشخیص مسیر وب به دیتابیس مراجعه نمی‌کنند. مسیرهای مدیریت همچنان کنترل ورود و CSRF قبلی را دارند.
- فایل‌های دارای هش Next.js با کش مرورگر طولانی و فونت‌ها با کش روزانه ارسال می‌شوند. پاسخ‌های بزرگ با gzip فشرده می‌شوند.
- محاسبات آماری داشبورد به چهار کوئری تجمیعی تبدیل شده‌اند؛ ترتیب دوره‌ها، مبلغ‌ها و خروجی‌های حسابداری حفظ می‌شود. تست داده واقعی SQLite، کل درخواست داشبورد با Anchor از قبل ذخیره‌شده را با حداکثر ۹ کوئری بررسی می‌کند.
- کتابخانه نمودار از بار اولیه مشترک جدا شده و فقط هنگام نمایش نمودار داشبورد بارگذاری می‌شود. در مقایسه فایل‌های script خروجی ساخت این نسخه با نسخه پیشین، JavaScript اولیه صفحات مدیریت از ۱٬۴۳۰٬۴۶۷ به ۱٬۰۴۲٬۰۶۷ بایت رسیده است؛ حدود ۲۷٪ کمتر، پیش از gzip.
- مترجم رابط، زیرشاخه‌های هم‌پوشانِ تغییرکرده DOM را در یک فریم دوباره پیمایش نمی‌کند.

این اعداد مربوط به خروجی ساخت و تست محلی‌اند، نه اندازه‌گیری VPS کاربر. خرابی شبکه، محدودیت منابع یا کندی خود پاسارگارد باید جداگانه روی سرور بررسی شود. تغییری در دیتابیس تولید یا کاربران واقعی انجام نشده است.

## اعمال نسخه

فایل‌های نسخه جدید را جایگزین و از ریشه پروژه اجرا کنید:

```bash
docker compose up -d --build api bot
```

پیش از بررسی سرعت، صفحه را یک بار با Refresh کامل باز کنید. مهاجرت جدید دیتابیس برای این تغییر لازم نیست. برای بررسی اتصال واقعی از داخل کانتینر می‌توانید راهنمای ابزار `scripts/diagnose_pasarguard_connection.py --help` را ببینید؛ ابزار اطلاعات ورود را در خروجی نمایش نمی‌دهد.
