# وضعیت تغییرات وب‌پنل D BOT

این شاخه پیش‌نویس است و برای انتشار عمومی یا نصب مستقیم روی VPS آماده اعلام نشده است. شماره نسخه عمومی فعلاً تغییر نکرده است.

## پیاده‌سازی‌شده

- نمایش نسخه و شماره ساخت مستقل در سایدبار؛ بررسی `update.json` از یک commit مشخص روی مخزن رسمی. برای اصلاحات کوچک کافی است `build` افزایش یابد؛ GitHub Release لازم نیست.
- درخواست آپدیت با نشست مدیر و CSRF، صف تک‌درخواستی و سرویس مستقل systemd روی میزبان. وب‌پنل به Docker socket دسترسی ندارد.
- بررسی commit رسمی، تهیه pg_dump، ساخت و راه‌اندازی مجدد و health check. در شکست، تلاش برای بازگرداندن سورس قبلی انجام می‌شود؛ دیتابیس خودکار به عقب برنمی‌گردد و بکاپ برای بازیابی دستی حفظ می‌شود.
- نصب سرویس آپدیت هنگام نصب جدید و اجرای به‌روزرسانی CLI. نصب‌های قبلی ابتدا به یک اجرای دستی `dbot update` پس از انتشار تغییرات نیاز دارند.
- تبدیل ویزارد پایه به مراحل جدا همراه نوار پیشرفت و فارسی/انگلیسی؛ اتصال و ذخیره سرور پیش از تکمیل راه‌اندازی و انتخاب قابلیت‌ها.
- تنظیم مشترک قابلیت‌های نمایندگی، OpenVPN، تست، کیف پول و آموزش. تنظیمات فاقد کلید در نصب‌های قدیمی رفتار قبلی را حفظ می‌کنند. وجود سرور میکروتیک فعال ابزار OpenVPN را نمایش می‌دهد.
- پنهان‌سازی منوهای غیرفعال در وب‌پنل و مینی‌اپ و کنترل مسیرهای مستقیم مرتبط. تنظیمات قابلیت‌ها بعداً از Settings قابل تغییر است.
- حفظ عکس و متن رسید؛ در تأیید/رد فقط دکمه وضعیت عوض می‌شود. حذف پیام شروع ساخت و گزارش مفصل تکراری برای رسید، و حفظ پیام کوتاه پس از تحویل. گزارش پرداخت کیف پول حفظ شده است.
- Recent Orders فقط سفارش دارای رسید ارسالی را نشان می‌دهد؛ آمار فروش تغییری نکرده است.
- پذیرش scope قدیمی `all` در مسیرهای نمایندگی اصلاح شده و انتخاب «Public + Reseller» به فرم سرور اضافه شده است. کلید خارجی یا شناسه‌های سوابق قبلی تغییر نمی‌کنند.
- آموزش متنی و قوانین در خود مینی‌اپ نمایش داده می‌شوند.
- انتخاب سرور تست در ربات و مینی‌اپ از میان سرورهای مجاز تنظیم‌شده. مشتری‌های قدیمی API بدون server_id رفتار چندسروری قبلی را حفظ می‌کنند.
- تعرفه حجم/روز با بازه‌های صحیح و نرخ تومان به‌ازای گیگ و روز؛ محاسبه فقط در سرور؛ پلن مستقل غیرفعال برای نگهداری مشخصات ثابت هر خرید و جلوگیری از تغییر سفارش قبلی با ویرایش تعرفه مادر. مسیر کیف پول و کارت و Telegram و Mini App از پلن ذخیره‌شده استفاده می‌کنند.
- حذف گزارش خطای timeout ارتباط تلگرام از ارسال مستقیم مدیر و کانال خطا، همراه حفظ لاگ محلی. timeout پنل‌های ارائه‌دهنده پنهان نمی‌شود.
- شناسه منشأ و workflow گواهی منشأ برای آرشیو سورس رسمی. این ابزار اثبات منشأ است؛ کشف فوری و قطعی همه کپی‌های تغییرنام‌یافته را تضمین نمی‌کند.

## هنوز تکمیل نشده

- ویزارد کامل تمام تنظیمات: تنظیم کارت‌ها، پلن‌ها، نمایندگی، تست، مینی‌اپ و بکاپ در مراحل اختصاصی و ذخیره/ادامه قابل‌بازیابی هر مرحله. ویزارد فعلی فقط مراحل پایه و انتخاب قابلیت‌ها را پوشش می‌دهد.
- نصب وابستگی‌ها به‌صورت انتخابی و کاهش مصرف دیسک. feature flag فقط اجرای/نمایش قابلیت را کنترل می‌کند؛ Dockerfile فعلی هنوز Xray و وابستگی‌های مشترک را می‌سازد.
- ادغام خودکار رکوردهای سرور تکراری قدیمی و بازنگری کامل همه مسیرها. فقط پذیرش سرور مشترک اصلاح شده؛ حسابداری و کلیدهای خارجی عمداً بازنویسی نشده‌اند.
- اتصال عملیاتی NX. API رسمی `/api/v1` با Bearer token، صفحه‌بندی و Idempotency-Key بررسی شد، اما گزینه سرورِ آماده فروش اضافه نشده است. مرجع: https://docs.nx-panel.org/reference/api و https://github.com/nx-panel/panel
- اتصال عملیاتی Darvish Bridge. بسته `darvish_bridge_1.0.0_mvp.zip` بررسی شد؛ نسخه فعلی درخواست `product_kind=digital` را رد می‌کند. هیچ سفارش VPN به‌عنوان کالای فیزیکی ثبت نشده و هیچ روش پرداخت ناقص به مشتری نمایش داده نشده است. قرارداد پرداخت و وب‌هوک پایدارِ جلوگیری از تکرار و تأیید مبلغ باید تکمیل شود.
- نمایش ویدیوی آموزش داخل مینی‌اپ؛ فعلاً متن، لینک دانلود و قوانین نمایش داده می‌شوند.
- آزمایش عملی آپدیت و بازگشت روی VPS آزمایشی و دیتابیس PostgreSQL با داده واقعی نسخه قبلی.

## بررسی انجام‌شده

۱۳۵ تست مرتبط با خرید و کیف پول، تعرفه، نمایندگی، تست، تبدیل، تنظیمات و خطا پاس شدند. ساخت production رابط Next.js و TypeScript موفق بود. Python compile و bash syntax و JavaScript تولیدی ویزارد بررسی شدند. اجرای مرورگر محلی به‌دلیل محدودیت socket محیط ممکن نشد؛ بررسی دیداری و تعاملی نهایی انجام نشده است. آزمون عملی Docker/systemd روی VPS نیز انجام نشده است.

## انتشار پس از تکمیل و بررسی

ابتدا موارد باز و آزمایش مهاجرت تکمیل شوند. سپس `version` در `update.json` با نسخه عمومی هماهنگ و `build` برای هر به‌روزرسانی افزایش یابد. فایل manifest باید روی همان commit سورس منتشر شود. سرویس میزبان فقط commit رسمی فعلی `main` را می‌پذیرد. این شاخه نباید پیش از بررسی با main ادغام شود.
